01. PROJECT OVERVIEW
================================================================

CloudProfile is a full-stack web application that combines:

- React/Vite frontend
- Node.js/Express backend
- MongoDB database
- JWT-based authentication
- AWS S3 object storage
- Docker containerization
- AWS EC2 deployment
- Nginx reverse proxy
- CI/CD automation
- LangChain-based AI project assistant
- Groq as the LLM provider

The application is designed as a single project demonstrating
how a modern web application can be developed, containerized,
deployed, automated, and enhanced with an AI assistant.

The AI assistant is designed to answer questions about the
CloudProfile project itself, including its architecture,
technology stack, project structure, implementation details,
and development workflow.

03. FRONTEND ARCHITECTURE
================================================================

The frontend is built using React with TypeScript and Vite.

React is responsible for the component-based user interface.
Vite is used as the frontend build tool and development server.
Tailwind CSS is used for styling and responsive UI development.

The frontend communicates with the backend through HTTP REST APIs.

MAIN FRONTEND RESPONSIBILITIES:

- User interface rendering
- User registration and login flows
- Profile management
- API communication
- Authentication state handling
- Profile/avatar interaction
- Theme switching
- AI assistant interface

The frontend does not directly access MongoDB.

The frontend communicates with the backend API, and the backend
handles database operations and AWS services.

05. AUTHENTICATION AND AUTHORIZATION
================================================================

CloudProfile uses JWT-based authentication.

Authentication flow:

1. User submits signup or login credentials.
2. Backend validates the request.
3. Backend verifies the user credentials.
4. Backend generates a JWT after successful authentication.
5. JWT is returned to the client.
6. Client uses the token when calling protected APIs.
7. Authentication middleware validates the JWT.
8. Authorized requests continue to the controller/service layer.

JWT secrets are stored using environment variables rather than
being hardcoded in the source code.

Protected operations require successful authentication.

Authentication is handled by the backend. The frontend is
responsible for managing the authenticated user experience and
sending the required authentication information with API requests.

07. AWS S3 — FILE STORAGE
================================================================

AWS S3 is used for storing user avatar/profile images.

The application uploads avatar files to an S3 bucket instead of
storing binary image data directly inside MongoDB.

AVATAR UPDATE FLOW:

1. User selects a new avatar.
2. Frontend sends the file to the backend.
3. Backend uploads the new file to S3.
4. Database/profile information is updated with the new avatar
   information.
5. After the new upload succeeds, the previous avatar can be
   deleted from S3.

This approach keeps object storage separate from application
metadata.

MongoDB stores application/profile information while S3 stores
the actual image objects.

15. APPLICATION FLOW
================================================================

A typical user request follows this architecture:

1. User interacts with the React frontend.
2. Frontend sends an HTTP request to the backend.
3. Nginx receives and routes the request.
4. Express handles the API request.
5. Middleware performs authentication/validation where required.
6. Controller processes the request.
7. Service layer executes business logic.
8. Backend communicates with MongoDB, S3, or the AI service.
9. Backend returns the result.
10. Frontend displays the response.

================================================================
18. RAG AND PROJECT KNOWLEDGE
================================================================

The AI assistant uses a Retrieval-Augmented Generation approach
to provide project-specific answers.

Project documentation is divided into meaningful sections
before embeddings are generated.

Example knowledge sections:

- Project Overview
- Technology Stack
- Frontend Architecture
- Backend Architecture
- Authentication
- MongoDB
- AWS S3
- Docker
- AWS EC2
- Nginx
- CI/CD
- API Architecture
- Project Structure
- Deployment Architecture
- AI Assistant
- LangChain
- Groq

Each section can be converted into an embedding and stored in a
vector database.

When a user asks a question:

1. The question is converted into an embedding.
2. Similar project-knowledge chunks are retrieved.
3. Retrieved chunks are provided as context to the LLM.
4. The LLM generates an answer using the retrieved context.

This reduces the need to place the entire project documentation
inside every prompt.
